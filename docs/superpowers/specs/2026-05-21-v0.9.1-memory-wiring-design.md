# v0.9.1 — MemoryPort wiring

**Status:** Proposed (2026-05-21) — implements the post-v0.9.0 wiring half of [ADR-025](../../architecture/adr/ADR-025-memory-port-and-managed-store-adapter.md). v0.9.0 shipped the `MemoryPort` Protocol and `LocalFileMemoryAdapter`; this spec wires them into the `spectra analyze` call site.

**Author:** Vivek Kumar, Head of Engineering
**Public commitment honoured:** *"v0.9.0 ships the port + LocalFileMemoryAdapter. The `spectra analyze` call site that deposits + reads lands in v0.9.1 alongside the ADR-ingest + post-Stage-6 hook."*

---

## 1. Goal & non-goals

**Goal.** Make the v0.9.0 `MemoryPort` observable to users. Three concrete wirings: a post-Stage-6 `scan_completed` deposit, a Stage-2 read that injects prior context into the MetaPrompter's planning prompt, and a Stage-1 ADR ingest that turns the repo's own architecture record into searchable events. After v0.9.1, run-2 of `spectra analyze` against the same repo demonstrably reads what run-1 deposited — the tweet promise ("this finding was waived 6 weeks ago for X reason") surfaces in the MetaPrompter prompt context before the scan re-flags it.

**Non-goals.** No new event kinds beyond the three named in ADR-025 (`scan_completed`, `waiver_added`, `adr_ingested`). No `spectra ask`, no `spectra brief`, no `ManagedAgentMemoryAdapter`, no `drift_detected` deposit — those are v0.10.0. No per-developer memory (deferred per ADR-025 to Q5+). No memory-store telemetry surfaced on the terminal — the cache observer pattern is the right model and we defer adoption until usage is non-trivial. No schema migration tooling — first ship, fresh schema, future bumps invalidate via the same composite-key discipline used in ADR-021.

## 2. Architecture overview

The composition root owns adapter selection and binds the wired port onto `PipelineContext.memory_port`. The use-case layer reads only the Protocol. Three stages call it; everything else is unchanged.

```
┌──────────────────────────── Layer 4 (infrastructure) ────────────────────────────┐
│                                                                                  │
│   main.py                                                                        │
│     _resolve_memory_dir()  ──► picks dir (CLI > env > default)                   │
│     _provision_memory()    ──► LocalFileMemoryAdapter(db_path)                   │
│     _safe_ingest_adrs()    ──► glob workspace, deposit adr_ingested events       │
│                                  │                                               │
│                                  ▼                                               │
│   PipelineContext(memory_port=…)                                                 │
│                                  │                                               │
└──────────────────────────────────┼───────────────────────────────────────────────┘
                                   │  (Protocol-shaped, no infra import below)
┌──────────────────────────────────┼───── Layer 2 (use_cases) ─────────────────────┐
│                                  ▼                                               │
│   analyze_repository.py                                                          │
│                                                                                  │
│     Stage 2: PLAN       ──► _safe_build_memory_context(ctx)                      │
│                              ctx.memory_port.query_events(kind=…) × 3            │
│                              → "Prior context" paragraph                         │
│                              → meta_prompter.run(file_tree + prior_context)      │
│                                                                                  │
│     Stage 6: REPORT     ──► _safe_deposit_scan_completed(ctx, report)            │
│                              ctx.memory_port.append_event(scan_completed)        │
│                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Three seams, one Protocol. The MetaPrompter still receives only file-tree + a short text paragraph (≤500 tokens of prior context); we do not breach the "file tree only, ≤5K tokens, never full code" agent hard rule.

**Resolution on ADR ingest placement:** the composition root owns workspace globbing (per explore agent recommendation + ADR-025 classification). The use-case layer never imports `pathlib` for ADR discovery. ADR ingest is a Layer 4 helper that deposits through the same `MemoryPort` instance later passed into `PipelineContext`.

## 5. Pydantic model additions

`MemoryEvent.payload` is already typed `dict[str, object]` (frozen at the entity layer). We do not add Pydantic subclasses for each kind — instead we add three module-level `TypedDict`s in `src/spectra/use_cases/memory_payloads.py` plus three thin builder functions that return `MemoryEvent` instances. This keeps `entities/memory.py` untouched (it is shipped in v0.9.0 and used by paid adapters that may carry a richer payload), and centralises payload shape contracts in Layer 2 where the writers live.

### 5.1 `scan_completed`

```python
class ScanCompletedPayload(TypedDict):
    scan_id: str               # ctx.run_id; UUIDv7 hex
    overall_score: float       # 0.0–100.0, rounded to 2dp
    overall_grade: str         # "A+" .. "F"
    finding_counts_by_severity: dict[Literal["critical","high","medium","low","info"], int]
    dimension_scores: dict[Literal["architecture","security","quality","documentation","maintainability","performance"], float]
    cost_usd: float            # rounded to 4dp
    duration_seconds: float    # rounded to 2dp
    is_degraded: bool          # mirrors report.is_degraded
```

`event.id` = `f"scan:{scan_id}"`. Idempotent on re-run of the same `run_id`.

### 5.2 `waiver_added` (reader only in v0.9.1; writer ships with `spectra waive` enhancement)

```python
class WaiverAddedPayload(TypedDict):
    waiver_id: str
    rule_id: str
    file_path: str
    line_start: int
    reason: str                # ≤ 280 chars
    approved_by: str
    expires_at: str | None
```

`event.id` = `f"waiver:{waiver_id}"`. Idempotent.

### 5.3 `adr_ingested`

```python
class AdrIngestedPayload(TypedDict):
    adr_path: str              # workspace-relative, POSIX separators
    title: str
    status: str
    date: str | None
    body_excerpt: str          # first 500 chars
```

`event.id` = `f"adr:{sha256(adr_path)[:16]}"`. Idempotent.

## 6. Public CLI surface change

Two new options on `spectra analyze`:

```
--memory-dir DIR        Directory holding the per-repo memory DB. Defaults to
                        $SPECTRA_MEMORY_DIR, then $XDG_DATA_HOME/spectra/memory
                        ($HOME/.local/share/spectra/memory if XDG unset).
                        [env: SPECTRA_MEMORY_DIR]

--no-memory             Disable the memory port for this run. No reads, no
                        writes, no ADR ingest. CI-safe.
```

**Precedence (highest first).** `--no-memory` overrides everything. Otherwise: explicit `--memory-dir` > `SPECTRA_MEMORY_DIR` env var > default.

### Storage location decision

**Pick: `$XDG_DATA_HOME/spectra/memory/<sha256-of-canonical-repo-url>.db`.**

Reasons:
1. **Survives between runs for the clone-and-analyze flow.** HTTPS clones use `tempfile.mkdtemp` workspaces; a path inside the workspace is destroyed on `finally: shutil.rmtree(...)`.
2. **OS-standard.** `$XDG_DATA_HOME` is the conventional location for user-specific *data* (vs. `$XDG_CACHE_HOME` for regeneratable cache and `$XDG_STATE_HOME` for state). Memory is the audit-trail-shaped historical record — data, not cache.
3. **Hidden from the user's git, by construction.** A path inside the user's repo would have to be added to every `.gitignore` to avoid accidental commits.
4. **Single code path.** Local-path and HTTPS-clone inputs hit the same hashed-URL DB. No `is_local_path` branching.

Trade-off accepted: the tweet's literal phrasing (`.spectra/memory/`) is no longer the on-disk path. Documented in `--memory-dir` help text. Users who want the tweet's exact layout pass `--memory-dir .spectra/memory` explicitly.

Canonicalisation rules (`memory_db_for(repo_url)`):
- lower-case scheme + host
- strip trailing `.git`
- strip trailing `/`
- `file://` and bare local paths → resolved absolute path → sha256 of resolved path string

## 7. Failure-mode test matrix

Every cell is a unit test. Writes degrade, reads raise — per ADR-025 + v0.9.0 contract.

| Scenario | Surface | Expected behaviour | WARN message |
|----------|---------|---------------------|----------------|
| `append_event` fails (disk full) | Stage 6 deposit | Scan completes; report ships; warning logged | `SPEC-010: memory deposit failed; scan saved without memory entry` |
| `query_events` fails (corrupt DB) | Stage 2 read | Caller catches `AgentError(SPEC-010)`; MetaPrompter runs *without* prior context | `SPEC-010: memory unavailable; planning without prior context` |
| `query_events` fails on ADR ingest path | Stage 1 (pre-write probe) | Skipped quietly; ingest still attempts writes | (debug log only) |
| DB file locked by another spectra run | Stage 2 read | `AgentError(SPEC-010)` → degrade to no-context plan | `SPEC-010: memory unavailable; planning without prior context` |
| DB file missing on first run | All hooks | Adapter lazy-creates at `0o700`/`0o600`; reads return `()`; writes succeed | (no warning) |
| Memory dir not writable | First append | `OSError` caught at adapter; degrade to one-shot WARN | `SPEC-010: memory dir not writable; this run will not deposit` |
| Corrupt schema | First read | `AgentError(SPEC-010)` raised at use case; degrade | `SPEC-010: memory schema unreadable; planning without prior context` |
| `--no-memory` set | All three hooks | `ctx.memory_port is None`; every helper returns early; no logs | n/a |
| ADR dir missing entirely | Stage 1 ingest | `_safe_ingest_adrs_at_root` returns 0 events | (debug log "no ADR directory found") |
| ADR file malformed (no H1, no Status) | Stage 1 ingest | Parser yields event with `title=""`, `status="unknown"` | (info log "ADR parse fell back to filename") |
| ADR re-ingest on run 2 | Stage 1 ingest | `INSERT OR IGNORE` on same id → no duplicate row | (no log) |
| `MemoryEvent` constructor rejects payload | Stage 6 deposit | `ValueError` caught at helper boundary | `SPEC-010: memory event malformed; scan saved without entry` |

All WARN rows use `logging.getLogger("spectra.memory").warning(...)`; no `print()`.

## 9. Acceptance criteria

Verbatim from handoff:

1. **Deposit visible to user.** After run 1, the sqlite DB at the resolved memory path contains exactly one row with `kind="scan_completed"` whose payload matches §5.1. Verifiable via `sqlite3 <path> "SELECT kind, payload_json FROM events WHERE kind='scan_completed'"`.
2. **Two-run read demonstrable.** Run `spectra analyze https://github.com/leocder07/spectra` twice. Run 2's audit log (with `--audit-sink stdout`) surfaces "Prior context: 1 prior scan (B+, ..., …d ago). N ADRs recorded; latest: …" to the MetaPrompter.
3. **Idempotent appends.** `SELECT COUNT(*) FROM events WHERE kind='adr_ingested'` stays constant across run 2 onwards.
4. **Tests stay green at 2502+.** Final pytest count ≥ 2502 + (new tests). No prior tests fail.
5. **Claim equals reality.** README / tweet / release notes claims match shipped behavior. `--memory-dir` help text states the default explicitly.
