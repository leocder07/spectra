Architecture (3)

low Agent infrastructure co-located with composition root ~4.0h ✓ validated ▶
src/spectra/infrastructure/main.py
The agents/ subdirectory (agent_factory.py, base_agent.py) lives under infrastructure/ alongside main.py. While infrastructure is the correct outer layer for concrete implementations, the agent subsystem appears complex enough to warrant its own top-level adapter or dedicated infrastructure subdomain. Co-locating the composition root (main.py) with agent implementations may blur the distinction between wiring and implementation.
Recommendation: Consider moving main.py to a dedicated composition_root/ or bootstrap/ module, or at minimum ensure main.py only performs wiring (instantiation and injection) without containing business logic. The agents/ subdirectory is fine under infrastructure/ but should have clear boundaries.
low Missing barrel exports (__init__.py) visibility ~2.0h ▶
src/spectra/use_cases/__init__.py
The file listing does not include __init__.py files for the packages. Well-structured Clean Architecture projects use barrel exports to define the public API of each layer, preventing consumers from reaching into internal modules. Without explicit __init__.py files controlling exports, any module can import any internal symbol from any layer.
Recommendation: Add __init__.py files with explicit __all__ exports for each layer package (entities/, use_cases/, adapters/, infrastructure/). This enforces encapsulation and makes the public API of each layer explicit.
info Single adapter layer with only CLI controller ~0.5h ✓ validated ▶
src/spectra/adapters/cli_controller.py
The adapters/ layer currently contains only cli_controller.py. While this is appropriate for the current scope, the architecture should anticipate additional adapters (REST API, SDK interface, etc.) without requiring changes to inner layers. The current structure supports this extensibility.
Recommendation: When adding new adapters, create subdirectories (adapters/cli/, adapters/api/) to maintain organization. Ensure the CLI controller delegates to use cases and does not contain business logic.

low External API client libraries (anthropic, tiktoken) require version monitoring ~2.0h ✓ validated ▶
src/spectra/infrastructure/anthropic_adapter.py
The project depends on the 'anthropic' and 'tiktoken' Python packages as seen from the infrastructure adapter modules. Both libraries are relatively young and undergo frequent breaking changes. The anthropic SDK in particular has had multiple major version bumps with breaking API changes in 2024-2025. Without seeing the pinned versions, there is a risk of using outdated or vulnerable versions.
Recommendation: Verify anthropic SDK is >= 0.39.0 (latest stable) and tiktoken is >= 0.7.0. Pin with compatible-release constraints (e.g., anthropic~=0.39) to allow patch updates while preventing breaking changes. Monitor changelogs for both packages.
low Verify Dependabot is configured for pip ecosystem with appropriate update schedule ~0.5h ▶
.github/dependabot.yml
The presence of .github/dependabot.yml is positive. However, common misconfigurations include: targeting only 'github-actions' but not 'pip', setting update frequency too low (monthly instead of weekly), or not specifying the correct manifest path for pyproject.toml-based projects.
Recommendation: Ensure dependabot.yml includes a 'pip' package-ecosystem entry pointing to the directory containing pyproject.toml, with at minimum weekly update schedule. Consider adding 'github-actions' ecosystem as well for CI workflow action pinning.
