high Potential dependency direction concern: use_cases/orchestrate_agents.py may import infrastructure types ~4.0h ▶
src/spectra/use_cases/orchestrate_agents.py
The use case `orchestrate_agents.py` coordinates agent execution, but the concrete agent implementations (specialist_agent, critique_agent, meta_prompter) live in `infrastructure/agents/`. If the orchestrator imports concrete agent classes directly rather than depending on abstractions defined in `use_cases/interfaces.py`, this violates the Dependency Rule where inner layers must not depend on outer layers. The presence of `interfaces.py` suggests this may be handled correctly, but the risk is significant given the complexity of the agent subsystem.
Recommendation: Verify that `orchestrate_agents.py` only depends on abstract interfaces defined in `use_cases/interfaces.py` and entity types from `entities/`. Add import-linter rules to CI to enforce: use_cases may not import from infrastructure or adapters. The agent_factory in infrastructure should handle concrete instantiation.
medium Composition root (main.py) placed inside infrastructure layer ~2.0h ▶
src/spectra/infrastructure/main.py
The application entry point `main.py` is located at `src/spectra/infrastructure/main.py` inside the infrastructure layer. In Clean Architecture, the composition root (where dependency injection wiring happens) should sit at the outermost layer or in a dedicated bootstrap module, not within infrastructure. This conflates infrastructure concerns with application bootstrapping and makes it harder to swap infrastructure implementations.
Recommendation: Move `main.py` to `src/spectra/main.py` (package root) or create a dedicated `src/spectra/bootstrap/` module. The composition root should be the outermost ring that wires adapters, infrastructure, and use cases together without belonging to any single layer.

Security (10)

high Git adapter may be vulnerable to path traversal when reading repository files ~4.0h ▶
src/spectra/infrastructure/git_adapter.py
The git_adapter.py reads files from repositories for analysis. If file paths from the repository are not sanitized, a malicious repository could contain symlinks or path traversal sequences (e.g., ../../etc/passwd) that cause the tool to read files outside the intended repository directory. CWE-22: Improper Limitation of a Pathname to a Restricted Directory. OWASP A01:2021 Broken Access Control.
Recommendation: Resolve all file paths to their canonical form using os.path.realpath() and verify they remain within the repository root directory before reading. Reject symlinks pointing outside the repo boundary.
high HTML report generation may be vulnerable to XSS via unsanitized repository content ~3.0h ▶
templates/report.html.j2
The Jinja2 template (report.html.j2) generates HTML reports from analysis results that include repository file contents and AI-generated findings. If repository content or AI responses containing malicious JavaScript are not properly escaped in the template, opening the report in a browser could execute arbitrary scripts. CWE-79: Improper Neutralization of Input During Web Page Generation. OWASP A03:2021 Injection.
Recommendation: Ensure Jinja2 autoescape is enabled (autoescape=True or use the 'select_autoescape' option). Verify that no template variables use the '|safe' filter on user-controlled or AI-generated content. Apply Content-Security-Policy headers if reports are served via HTTP.
high Token budget manager may not prevent prompt injection via repository content ~8.0h ▶
src/spectra/use_cases/manage_token_budget.py
The manage_token_budget.py use case handles token budgeting for AI prompts that include repository source code. Recommendation: Implement prompt injection defenses: clearly delimit user-provided code from system instructions using XML tags or similar boundaries, add instruction-hierarchy markers, and consider content filtering for known prompt injection patterns in repository files before sending to the AI.

high Sequential agent execution likely bottleneck in orchestration ~8.0h ▶

high Anthropic API adapter likely makes synchronous blocking calls ~8.0h ▶
src/spectra/infrastructure/anthropic_adapter.py
The anthropic_adapter.py is the core I/O bottleneck as it communicates with the Anthropic API. Python's default HTTP clients are synchronous. If the adapter uses the synchronous Anthropic SDK client, it blocks the thread during each API call. Combined with sequential agent orchestration, this means the application is idle waiting for network I/O most of its runtime.
Recommendation: Use the async Anthropic client (anthropic.AsyncAnthropic) with async/await patterns. This enables concurrent API calls when combined with asyncio.gather() in the orchestrator. If async migration is too large, use concurrent.futures.ThreadPoolExecutor as an intermediate step.
