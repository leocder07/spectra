Performance (5)

low Potential lack of tiktoken encoder caching ~0.5h ✓ validated ▶
src/spectra/infrastructure/tiktoken_adapter.py
tiktoken encoder initialization is expensive (requires loading BPE merge files). If TiktokenAdapter instantiates a new encoder per call rather than caching the encoder instance, this could add significant latency to every token counting operation, especially when called repeatedly during budget management.
Recommendation: Cache the tiktoken encoder instance at the class or module level. Use `tiktoken.encoding_for_model()` or `tiktoken.get_encoding()` once and reuse the result. Consider using `functools.lru_cache` on the encoder factory method.
low Retry decorator exponential backoff may cause cascading delays under load ~4.0h ✓ validated ▶
src/spectra/infrastructure/retry_decorator.py
When multiple parallel agents hit API rate limits simultaneously, exponential backoff retries across all agents can compound total execution time significantly. If agents are awaited concurrently via asyncio.gather, one slow-retrying agent blocks the entire batch result.
Recommendation: Add jitter to backoff delays to prevent thundering herd. Consider implementing a shared rate limiter (e.g., asyncio.Semaphore) across agents rather than relying solely on per-request retry. Set a maximum total retry duration cap.
low Agent factory may create redundant instances without pooling ~2.0h ▶
src/spectra/infrastructure/agents/agent_factory.py
If AgentFactory creates new agent instances (and their associated API clients/connections) for each analysis dimension without reusing shared resources like HTTP connections or API clients, this adds unnecessary overhead for connection setup and teardown.
Recommendation: Share the Anthropic API client instance across agents created by the factory. Use connection pooling for HTTP clients (e.g., a shared httpx.AsyncClient or aiohttp.ClientSession).
low Progress reporter may introduce synchronous I/O overhead in async pipeline ~1.0h ▶
src/spectra/adapters/progress_reporter.py
If the progress reporter writes to stdout/stderr synchronously (e.g., using print() or sys.stdout.write()) within an async orchestration pipeline, it could block the event loop briefly on each progress update, especially with frequent updates across parallel agents.
Recommendation: Use async-compatible output or batch progress updates. If using Rich or similar libraries, ensure they don't block the event loop. Consider throttling progress updates to at most once per second.
low Token budget management may perform redundant counting on large codebases ~2.0h ✓ validated ▶
src/spectra/use_cases/manage_token_budget.py
For large repositories, token counting the entire codebase content multiple times (once per agent dimension) could be expensive. If manage_token_budget recounts tokens for the same content across different agents rather than caching the count, this wastes CPU cycles proportional to codebase size × number of agents.
Recommendation: Count tokens once for the full codebase content and cache the result. Pass pre-computed token counts to budget allocation logic. Consider memoizing token counts per file for incremental budget adjustments.
