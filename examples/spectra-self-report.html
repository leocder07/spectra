Performance (2)

medium Retry decorator may cause cascading latency spikes ~4.0h ▶
src/spectra/infrastructure/retry_decorator.py
The retry_decorator.py implements retry logic for infrastructure calls (likely LLM API calls). Without careful configuration of backoff strategy, max retries, and timeout budgets, retries on LLM API calls can cause significant latency amplification. In a parallel agent pipeline, one slow/retrying agent blocks the entire gather() call, negating the benefits of parallelism. If exponential backoff is used with high max_retries, a single failing agent could hold up the entire pipeline for minutes.
Recommendation: Implement a total timeout budget per agent execution (not just per-retry). Use jittered exponential backoff with a reasonable cap (e.g., max 3 retries, max 30s total). Consider adding a circuit breaker pattern. For parallel execution, use asyncio.wait() with timeout instead of unbounded gather() so one failing agent doesn't block others indefinitely.
medium Token budget management performs redundant tokenization passes ~4.0h ▶
src/spectra/use_cases/manage_token_budget.py
The manage_token_budget.py use case likely tokenizes content multiple times during budget allocation — once to measure current usage, again during truncation/fitting, and potentially again for validation. Each tokenization pass over large prompts (especially with context from git repository scanning of large repos) is O(n) in content length and involves BPE merge operations. For large repositories with extensive context, this compounds significantly.
Recommendation: Tokenize content once and work with token arrays/counts throughout the budget management pipeline. Cache token counts for content that hasn't changed. Consider a streaming/incremental approach where token counts are maintained as content is assembled rather than recomputed from scratch.
