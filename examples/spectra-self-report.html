medium Infrastructure layer contains application entry point (main.py) ~2.0h ▶
src/spectra/infrastructure/main.py:1
The application's main entry point (main.py) is located inside src/spectra/infrastructure/, which is an infrastructure concern. In Clean Architecture, the composition root / entry point should sit outside all layers (or at the outermost layer) to wire dependencies together. Placing it in infrastructure conflates infrastructure adapters with application bootstrapping and dependency injection.
Recommendation: Move main.py to src/spectra/ (package root) or create a dedicated src/spectra/bootstrap/ or src/spectra/composition_root.py. This separates the wiring/composition concern from infrastructure implementations and makes the dependency graph cleaner.
medium Adapters layer role ambiguity — adapters vs infrastructure boundary is unclear ~4.0h ▶

Both src/spectra/adapters/ and src/spectra/infrastructure/ contain 'adapter' classes (e.g., adapters/cli_controller.py, adapters/analysis_presenter.py vs infrastructure/anthropic_adapter.py, infrastructure/git_adapter.py, infrastructure/report_adapter.py). In Clean Architecture, 'adapters' (interface adapters) and 'infrastructure' (frameworks & drivers) are distinct rings, but the naming convention uses '_adapter' suffix in both layers, creating confusion about which layer a component belongs to and what the boundary semantics are.
Recommendation: Establish a clear naming convention: use 'controller', 'presenter', 'gateway' for the adapters layer and reserve '_adapter' suffix exclusively for infrastructure implementations of use-case-defined ports. Document this convention in CLAUDE.md or an ADR.

high Potential command injection in Git adapter ~4.0h ▶
src/spectra/infrastructure/git_adapter.py
The git_adapter.py likely executes Git commands (clone, log, diff, etc.) against user-supplied repository paths or URLs. If subprocess calls are constructed using string interpolation or shell=True without proper input sanitization, this creates a command injection vulnerability. CWE-78: Improper Neutralization of Special Elements used in an OS Command. OWASP A03:2021 Injection.
Recommendation: Use subprocess.run() with a list of arguments (not shell=True). Validate and sanitize repository paths/URLs against an allowlist pattern. Reject paths containing shell metacharacters (;, |, &, $, backticks). Consider using GitPython library instead of raw subprocess calls for safer Git operations.
medium Potential XSS in HTML report generation ~2.0h ▶
templates/report.html.j2
The project generates HTML reports (report_adapter.py, templates/report.html.j2, examples/*.html). If analysis findings containing user-controlled content (repository names, file paths, code snippets, commit messages) are inserted into HTML templates without proper escaping, this creates stored XSS vulnerabilities. CWE-79: Improper Neutralization of Input During Web Page Generation. OWASP A03:2021 Injection.
Recommendation: Ensure Jinja2 autoescape is enabled (autoescape=True or autoescape=select_autoescape()). Verify that no |safe filters are used on user-controlled data. Review report_adapter.py to confirm the Jinja2 Environment is configured with autoescaping enabled by default.
