high Agents subsystem nested inside infrastructure blurs layer boundaries ~8.0h ▶
src/spectra/infrastructure/agents/
The agents/ package (base_agent.py, specialist_agent.py, critique_agent.py, meta_prompter.py, agent_factory.py, specialist_prompts.py) lives under infrastructure/agents/. However, agent orchestration logic — deciding which agents to run, how to combine their outputs, prompt engineering strategies — is core application/domain logic, not an infrastructure concern. Infrastructure should be limited to I/O adapters (HTTP clients, file systems, databases). The current placement means domain-significant orchestration patterns are coupled to the infrastructure layer, making it harder to test agent logic independently of external services.
Recommendation: Split the agents package: (1) Move agent orchestration logic, prompt templates (specialist_prompts.py), and the factory pattern into use_cases/ or a new domain-level agents/ package. (2) Keep only the thin adapter that calls the Anthropic API in infrastructure/. The base_agent and specialist logic should depend on use_cases/interfaces.py, not live alongside the Anthropic adapter.
medium Infrastructure layer contains application entry point (main.py) ~2.0h ▶
src/spectra/infrastructure/main.py:1
The main.py module, which serves as the application composition root and entry point, is located inside src/spectra/infrastructure/main.py. In Clean Architecture, the composition root (where dependency injection wiring happens) should sit outside all layers — typically at the project root or in a dedicated 'bootstrap' or 'app' module. Placing it in infrastructure conflates the wiring/startup concern with external service adapters.
Recommendation: Move main.py to src/spectra/main.py or src/spectra/bootstrap.py as a top-level composition root that imports from all layers but belongs to none. This clarifies that it is the outermost shell responsible for wiring dependencies.
medium Potential dependency direction violation: adapters and infrastructure at same level ~4.0h ▶
src/spectra/adapters/cli_controller.py
In strict Clean Architecture, adapters (interface adapters) and infrastructure (frameworks/drivers) are distinct layers with infrastructure being the outermost. Here, both src/spectra/adapters/ and src/spectra/infrastructure/ exist as sibling packages. The CLI controller (adapters/cli_controller.py) likely needs to wire together use cases with infrastructure implementations, which means it may import from infrastructure — creating a lateral dependency rather than a clean inward-only dependency flow. The adapters layer (cli_controller, presenters) and infrastructure layer (anthropic_adapter, git_adapter, report_adapter) appear to be at the same architectural level without a clear hierarchy.
Recommendation: Clarify the relationship: either (1) merge adapters/ into infrastructure/ since both are 'outer ring' concerns, with sub-packages for 'driving' (CLI) and 'driven' (API clients) adapters following Hexagonal Architecture naming, or (2) establish a clear composition root that wires adapters to infrastructure, keeping them as true siblings that never import from each other.

high Git Adapter May Be Vulnerable to Path Traversal ~4.0h ▶
src/spectra/infrastructure/git_adapter.py
The git_adapter.py handles repository paths and file system operations. If user-supplied repository paths are not properly validated and sanitized, an attacker could use path traversal sequences (e.g., ../../etc/passwd) to read arbitrary files on the system. CWE-22: Improper Limitation of a Pathname to a Restricted Directory. OWASP A01:2021 Broken Access Control. This is especially critical since the tool reads source code files from disk.
Recommendation: Implement strict path validation using os.path.realpath() to resolve symlinks and verify the resolved path is within the expected repository root. Reject paths containing '..' sequences. Use pathlib.Path with resolve() and check that the resolved path starts with the allowed base directory.
high Prompt Injection Risk in Agent Pipeline ~8.0h ▶
src/spectra/infrastructure/agents/base_agent.py
The multi-agent pipeline (specialist_agent.py, base_agent.py, meta_prompter.py) processes source code from analyzed repositories and includes it in prompts sent to Anthropic's API. Malicious code in analyzed repositories could contain prompt injection payloads designed to manipulate the AI agents' behavior, potentially causing them to produce misleading analysis results or exfiltrate data through crafted outputs. CWE-74: Improper Neutralization of Special Elements in Output Used by a Downstream Component ('Injection'). This is an emerging attack vector specific to LLM-based applications.
Recommendation: Implement prompt injection defenses: (1) Clearly delimit user-supplied code from system instructions using XML tags or structured separators, (2) Add system-level instructions that explicitly tell the model to treat code content as data only, (3) Validate and sanitize agent outputs before including them in downstream prompts, (4) Consider implementing output validation to detect anomalous responses.

templates/report.html.j2
The project generates HTML reports (report_adapter.py using templates/report.html.j2). If Jinja2 autoescaping is not enabled or if the template uses the |safe filter on user-controlled data (analysis findings from potentially malicious repositories), this creates a stored XSS vulnerability. CWE-79: Improper Neutralization of Input During Web Page Generation. OWASP A03:2021 Injection.
