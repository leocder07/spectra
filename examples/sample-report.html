Architecture (10)

medium Prototype augmentation pattern for request/response objects
lib/request.js
Express augments the native Node.js http.IncomingMessage and http.ServerResponse prototypes via request.js and response.js respectively. This mixin/monkey-patching pattern, while effective and well-understood in the Express ecosystem, makes it harder to reason about the full API surface of req/res objects and can conflict with other libraries that augment the same prototypes.
Recommendation: This is a fundamental design decision of Express. For Express 5.x or future major versions, consider composition over inheritance (wrapping req/res in proxy objects) to reduce prototype pollution risks.
medium Application module likely has high responsibility density
lib/application.js
lib/application.js is responsible for app configuration (settings), middleware mounting (use), route registration (get/post/etc.), rendering (render), engine registration (engine), parameter handling (param), and listener setup (listen). This single module carries the bulk of the framework's API surface, making it a potential maintenance bottleneck.
Recommendation: Consider splitting application.js into focused mixins (e.g., app-settings.js, app-routing.js, app-rendering.js) that are composed together. This would improve testability and readability without changing the public API.
low MVC example demonstrates solid architectural pattern but uses custom bootstrapping
examples/mvc/lib/boot.js
The examples/mvc/ directory implements a full MVC pattern with controllers (main, pet, user, user-pet), a database abstraction (db.js), views co-located with controllers, and a custom boot.js loader. The boot.js module auto-discovers controllers by scanning the filesystem, which is a convention-over-configuration approach. However, this custom bootstrapping is tightly coupled to the directory structure convention.
Recommendation: The MVC example is good for demonstration. For production use, recommend explicit controller registration or a well-tested loader library to avoid fragile filesystem-based discovery.
