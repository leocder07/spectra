Architecture (12)

medium Monolithic routing module handles too many responsibilities ~40.0h ▶
fastapi/routing.py
fastapi/routing.py is the largest and most complex module in the codebase, handling route registration, request/response serialization, dependency resolution orchestration, OpenAPI schema contribution, WebSocket routing, and APIRouter composition. This single file likely exceeds 1000+ lines and combines endpoint execution logic with schema generation and router composition, making it difficult to modify one concern without risking others.
Recommendation: Consider extracting request/response serialization logic and OpenAPI schema contribution into separate modules (e.g., fastapi/routing/serialization.py and fastapi/routing/schema.py) while keeping the core routing registration in the main module. This would improve testability and reduce cognitive load.
medium Dependency injection utilities concentrated in a single large module ~16.0h ▶
fastapi/dependencies/utils.py
The dependency injection system is split between fastapi/dependencies/models.py (data models) and fastapi/dependencies/utils.py (resolution logic). While the models separation is good, utils.py likely contains all dependency resolution, caching, yield-dependency lifecycle management, and parameter analysis in one file. The complexity of features like dependency caching, yield-based dependencies with exit stacks, and context variable scoping suggests this module would benefit from further decomposition.
Recommendation: Consider splitting dependency resolution into: parameter analysis/extraction, dependency graph resolution, and yield/contextmanager lifecycle management as separate submodules within fastapi/dependencies/.
medium OpenAPI generation tightly coupled with routing ~16.0h ▶
fastapi/openapi/utils.py
The OpenAPI schema generation (fastapi/openapi/utils.py) must deeply understand the routing internals to extract schema information. The openapi/ package contains models.py for OpenAPI data structures, docs.py for Swagger/ReDoc HTML generation, and utils.py for schema generation from routes. The coupling between routing.py and openapi/utils.py means changes to route registration often require corresponding changes to schema generation, violating the Open/Closed principle.
Recommendation: Consider introducing a schema contribution interface/protocol that route objects implement, allowing openapi/utils.py to collect schema information through a well-defined contract rather than reaching into routing internals.

Security (9)

medium Tutorial examples use hardcoded secret key for JWT signing ~2.0h ▶
docs_src/security/tutorial005_an_py310.py
The tutorial documentation examples (docs_src/security/tutorial004_*.py, tutorial005_*.py) for OAuth2 with JWT tokens typically contain a hardcoded SECRET_KEY value (e.g., 'secret' or a fixed string) used for signing JWT tokens. While these are documentation examples, users frequently copy-paste tutorial code directly into production. CWE-798: Use of Hard-coded Credentials. OWASP A07:2021 Identification and Authentication Failures.
Recommendation: Add prominent warnings in tutorial code comments that SECRET_KEY must be replaced with a cryptographically random value loaded from environment variables. Consider using os.environ.get() in examples to reinforce best practices.
medium HTTP Basic Auth timing attack vulnerability in example code ~1.0h ▶
docs_src/security/tutorial007_an_py310.py
The HTTP Basic Auth tutorial examples (docs_src/security/tutorial006_*.py, tutorial007_*.py) and the corresponding advanced security documentation (docs_src/security/tutorial006_an_py310.py) demonstrate credential comparison. The FastAPI docs do show secrets.compare_digest usage, but the pattern of comparing username and password separately can still leak timing information about which field failed. CWE-208: Observable Timing Discrepancy. OWASP A07:2021 Identification and Authentication Failures.
Recommendation: Ensure all HTTP Basic Auth examples consistently use secrets.compare_digest for both username and password, and always perform both comparisons regardless of the first result to prevent timing-based enumeration.
medium OAuth2PasswordBearer does not enforce HTTPS by default ~4.0h ▶
fastapi/security/oauth2.py
The OAuth2PasswordBearer security scheme in fastapi/security/oauth2.py accepts a tokenUrl parameter but does not warn or enforce that the token URL should use HTTPS in production. Sending OAuth2 credentials over plain HTTP exposes tokens and passwords to interception. CWE-319: Cleartext Transmission of Sensitive Information. OWASP A02:2021 Cryptographic Failures.
Recommendation: Consider adding a runtime warning when tokenUrl does not start with 'https://' and the application is not in debug/development mode. Document the HTTPS requirement prominently.
medium CORS tutorial example uses overly permissive wildcard configuration ~1.5h ▶
docs_src/cors/tutorial001_py310.py
The CORS tutorial examples (docs_src/cors/tutorial001_py310.py, tutorial001_py39.py) demonstrate CORSMiddleware with allow_origins=['*'] or broad origin lists, allow_credentials=True, and allow_methods=['*']. Users copying this configuration into production create a significant security risk by allowing any origin to make credentialed cross-origin requests. CWE-942: Permissive Cross-domain Policy. OWASP A05:2021 Security Misconfiguration.
Recommendation: Add prominent warnings in CORS tutorial examples that wildcard origins with credentials enabled is insecure. Show a restrictive example as the primary pattern and the permissive one only as a development-only configuration.
